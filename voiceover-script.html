“Hello! In this demonstration, I will showcase Forge — an autonomous coding agent extension for VS Code powered by TrueForge.

Task A: Targeted Inline Code Editing 0:15 – 1:05 (50s)
Spoken Text

“Starting with Task A: targeted inline code editing. Here in helpers.py, we have the get_debug_flag function. Currently, it only checks for ‘0’, ‘false’, and ‘no’. If we set FLASK_DEBUG to ‘off’, it still evaluates to True.

I select lines 28 to 34 and hit Ctrl+Shift+I to invoke Forge Inline Edit. I give it this instruction:

‘Treat the values ‘off’ and ‘n’ as false as well, case-insensitively, and update the docstring to list every value that is treated as false.’

The inline agent analyzes the highlighted code range and computes a surgical unified diff. Forge does not overwrite the file — it stages hunks with CodeLens controls right above the code, allowing per-hunk inspection and review.

I click ‘Accept All’. The function and docstring are updated cleanly in-place without touching any other code.

Now verifying in the terminal with FLASK_DEBUG set to ‘off’: it outputs False — confirming the bug is resolved.”

Task B: Multi-File Autonomous Feature Implementation 1:05 – 2:30 (85s)
Spoken Text

“Moving to Task B: building a complete feature across multiple files autonomously.

I open the Forge Agent sidebar and submit our requirement:

‘Add a new built-in CLI command flask config that prints the loaded application’s configuration as JSON, masking the values of any key containing SECRET, PASSWORD, TOKEN or KEY as ‘***’. It must appear in flask --help, be covered by a test, and be documented alongside the other built-in commands.’

Immediately, Forge initiates its autonomous tool execution loop.

First, notice the Context Ledger at the top of the panel: the agent uses note_context to record cli.py, test_cli.py, and cli.rst with token estimates, keeping our prompt budget strictly optimized.

Then it proceeds through structured multi-file edits: implementing the Click command in cli.py, adding test coverage in test_cli.py, and documenting the command in cli.rst.

Switching to our browser at localhost:8790/sessions, we can see the live TrueForge session created by forge-agent, capturing the turn lifecycle and tool invocations.

Back in VS Code, we accept the staged proposals. Let’s run the three verifications in the terminal:

First, running pytest: all 58 tests pass — including the 3 new unit tests covering JSON serialization, key masking, and CLI registration.
Second, running flask config: it outputs formatted JSON with sensitive keys like SECRET_KEY safely masked as three asterisks.
Finally, running flask --help: the config command appears in the built-in commands list.”

Task C: Model Resilience & Automatic Fallback 2:30 – 3:25 (55s)
Spoken Text

“Finally, Task C demonstrates Resilience and Model Fallback.

In TrueForge, I deliberately switch the primary agent forge-inline to an unauthenticated model. This simulates an upstream model outage or severe rate-limiting.

Now returning to VS Code, I trigger inline edit with Ctrl+Shift+I and send a prompt:

‘Add a comment explaining what this function does.’

When the primary agent fails to respond within 15 seconds, Forge detects the failure automatically. Notice the warning notification appears: ‘Primary agent failed. Switched automatically to fallback agent.’

Crucially, the editor remained completely responsive throughout — no freezing, no modal blocks.

Running git status in the terminal confirms our workspace remains clean without corrupted files or half-baked edits.

I’ll now restore the model in TrueForge back to Gemini.”
